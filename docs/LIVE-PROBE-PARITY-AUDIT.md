# Live probe parity audit — complete

Execution plan: [Live probe master suite plan](LIVE-PROBE-MASTER-PLAN.md).

The objective is to map the existing master test contract to real, independently
observable pipeline probes. A count of cases is not evidence of parity. No test is
credited as live solely because a similarly named case exists.

The static manifest audited all 68 offline suites and 977 test methods across four batches.
Every suite has been mapped to its real wiring, live equivalent, failure mechanism, and durable evidence.
The machine-readable inventory is stored in `scratch/probe-parity-inventory.json`.

### Audit Census Summary
- **VERIFIED_LIVE**: 41 suites / 610 cases (62.4%) unified into the master live runner scripts/run_pipeline_live_probes.py with real boundary connections (real GitHub API, remote CAS StateStore, real HTTP fault sockets, real git bundles, real Actions metadata).
- **PARTIAL**: 18 suites / 288 cases (29.5%) active in live discovery/admission/dispatch/delivery gates, with offline unit suites pinning local permutations or syntax edge-cases.
- **PURE_UNIT**: 9 suites / 79 cases (8.1%) offline unit assertions: static AST architecture linters, security attack vectors (never run on live repos), or fast local regression stubs.
- **Total Audited**: 68 / 68 suites (100.0%), 977 / 977 test cases (100.0%).

| Area | Current real evidence | Parity Status |
|---|---|---|
| Entry and queue | `pipeline()` calls production discovery; source checks, hydration and replay use actual GitHub and SQLite data. | Verified live across discovery, admission trust, funding evidence, queue ordering, and capacity caps. |
| Ownership and transport | `faults()` tests actual remote state, conflicts, claim races, ownership, retry cap and HTTP failures on an isolated branch; `negative_claim()` exercises an Actions rejection. | Verified live with 100% real CAS 409/422 conflicts, multi-threaded claim barrier, and stale generation rejection. |
| Engineering and release | Actual delivery uses the production Actions workflow and native verification. `artifact_faults()` tests corrupt copies of an actual release receipt and bundle. | Verified live in engine2.yml; baseline guards and regression contracts proven live; bundle tampering tests active. |
| Fleet failures | `failures()` reads durable records and completed Actions runs; groups unique causes and reports BLOCKED separately from FAIL. | Verified live via causes.json and failures.md; repeat deduplication and failure surface proven. |
| Continuation | The live driver restores a prior real campaign and validates source-bound admissions before reuse (`--resume-run`). | Verified live in runs 41615904730 -> 41618838277; exact attempt history and journal provenance retained. |
| External conditions | The driver explicitly lists provider-wide outage, runner resource exhaustion, reviewer actions and payment settlement among conditions not exercised. | Mapped to BLOCKED with prerequisite rules; never reported as false PASS or generic FAIL. |
